# Hindi i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Full applicant-facing Hindi per `docs/superpowers/specs/2026-08-01-hindi-i18n-design.md` — Flutter UI via ARB/gen_l10n, server-side language preference with rescore-on-switch, bilingual explanations (templated + LLM), and Hindi applicant-bound emails. Recruiter/admin surfaces stay English.

**Architecture:** One new column (`applicant_preferences.language`) is the single server-side language signal; the existing preferences PATCH rescore-trigger machinery delivers rescore-on-switch; the Flutter app resolves locale device-first/server-wins; emails localize in the `_render` string table; explanations localize via `ExplainContext.language`.

**Tech Stack:** Alembic + SQLAlchemy 2 (backend), pytest, Flutter `flutter_localizations` + `gen_l10n` ARB + Riverpod 4 codegen.

## Global Constraints

- Branch: `hindi-i18n` (already created; spec committed on it).
- Backend commands from repo root (`uv` only); app commands from `app/`.
- CI-verbatim gates: `uv run ruff check core/src api/src worker/src tests` · `uv run ruff format --check core/src api/src worker/src tests` · `uv run mypy` · `uv run pytest -v -m "not integration and not eval"` · `uv run pytest -v -s -m eval` · `uv run pytest -v -m integration` · app: `dart format --set-exit-if-changed lib test` · `flutter analyze` · `flutter test`.
- **Wire values never translate** — enums, slugs, query params stay English; only display strings localize.
- Language codes exactly `"en"` / `"hi"`; DB varchar + CHECK (no PG enum — `desired_role` precedent); `AppLanguage` StrEnum at the boundary.
- Recruiter/admin surfaces English-only: the Flutter `presentation/recruiter/` subtree and `employer_invite` email are exempt from localization (guard allowlists them).
- Hindi is Devanagari; Latin digits (no Devanagari numerals). Existing IST/₹/lakh formatting untouched.
- After touching any `@riverpod`/`@freezed`/l10n file: `dart run build_runner build --delete-conflicting-outputs` (gen_l10n runs via `flutter gen-l10n` / build). Widget tests use `ThemeData.light(useMaterial3: true)`.
- Hand-written migrations in `core/src/jobify/db/migrations/versions/` (next id `0027`); edit before `cd core && uv run alembic upgrade head`.
- All new integration tests carry module-level `pytestmark = pytest.mark.integration` (or live in files that do).
- ARB key convention: `<surface><Meaning>` camelCase (e.g. `feedEmptyHeadline`, `profileSignOut`, `commonRetry` for shared strings). `app_en.arb` is the source of truth with `@key` descriptions; `app_hi.arb` mirrors every key.
